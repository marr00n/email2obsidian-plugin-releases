# Product Requirements — Email2Obsidian Sync Plugin

## Background & Problem
Obsidian users currently lack a native, reliable way to fetch processed emails directly into their vault. Existing workarounds rely on manual downloads or personal scripts, which are brittle, inconsistent with attachment handling, and prone to duplication.

A first-class third party service in is required to handle this problem - Email2Obsidian (E2O). E2O allows users to send emails (including attachments) into a central ingestion service, where each message becomes a structured note accessible via a REST API. 

This app will be an Obsidian plugin for our third party service. It will fetch emails and attachments into Obsidian, providing a simple, predictable sync of new email-derived notes into Obsidian.

## Goals
- Fetch newly available Email2Obsidian notes (`/api/emails`, `/api/emails/:id`) and save them into Obsidian as Markdown documents.
- Support email subjects (`subject`), tags (`hashtags`), bodies (`markdownBody`), inline attachments, and file attachments appended to the end of the note.
- Ensure users can specify destination folders of notes and attachments, and avoid re-downloading already synced messages.
- Provide a minimal setup flow: API key, destination folder (required; default `E2Oinbox`), sync (manual and periodic).
- Prevent overwrites by collision-proofing note and attachment filenames with an incrementing numeric suffix until unique within their respective folders.

## Non-Goals
- Sending emails from Obsidian.
- Editing server-side Email2Obsidian content from within Obsidian.
- Mobile-specific UI beyond standard settings.

## Users & Stories
- Note-taker: “I want my emailed notes to appear in my vault automatically so I can integrate them into my existing workflows.”
- Researcher: “When I sync, I should get only new documents so I do not accumulate duplicates or overwrite unrelated files.”
- New user: “I need a simple setup—point to my endpoint, paste a api key, pick a folder, and run sync to obtain only documents not fetched before.”

## UX & Copy
- Use concise, descriptive labels in Settings.
- Provide short helper text under API Key fields outlining expected values.
- Command palette entry is explicit to ensure users understand this action fetches new notes.
- Errors show small notices for missing or invalid credentials; detailed sync logs available in the developer console.

## API Shape Notes
- `GET /api/emails`: returns `{ emails: [{ id, subject, createdAt, hashtags: string[] }], hasMore, nextCursor, tags }` with optional query params `cursor`, `sort` (`date-desc` default), `tag`, `search`.
- `GET /api/emails/:id`: returns `{ id, emailId, subject, hashtags: string[], markdownBody, createdAt, expiresAt, attachments: [{ id, fileName, fileSize, mimeType, createdAt, contentDisposition: inline|attachment }] }`.
- `GET /api/attachments/:id/download`: returns file stream;
- 400/403/404/500 for errors; all endpoints require `x-api-key` and are rate limited.

## Markdown Note Template
- Markdown template:
  - Frontmatter:
    ```
    ---
    title: <subject>
    created: <createdAt>
    tags: [<hashtags>, email2obsidian]
    email2obsidianID: <id>
    ---
    ```
  - Body text rendered from `markdownBody` as plain Markdown, with support for inline attachments (`contentDisposition: inline`, always present) embedded using standard Obsidian image/file syntax, referencing files saved to the attachment folder (or alongside the note if no folder is set).
  - Non-inline attachments (`contentDisposition: attachment`, always present) listed under a section `## Attachments` with links to the saved files in the attachment folder (or alongside the note if no folder is set), using `fileName` (preserved) for link text.
  - Inline placeholders are always `![](data:...)` and arrive in the same order as inline attachments; use positional replacement with no fallback remapping.
  - If an attachment folder is configured, both inline and non-inline references point to that folder; otherwise, attachments live beside the note.
  - Filenames are sanitised and collision-safe via an incrementing numeric suffix applied until unique per folder.
  - All API calls use the hard-coded base endpoint `https://email2obsidian.com/` with `x-api-key` auth.

## Success Metrics
- Setup success rate: proportion of users who complete the API key / folder configuration without support requests.
- Sync reliability: proportion of sync runs executed without failures; discrepancy rate between server item count and downloaded notes.
- Idempotency: % of reruns that correctly produce zero rewrites when nothing has changed.

## Release Scope (v1)
- Manual sync command.
- Periodic sync setting with optional run-on-open toggle; initial run occurs immediately on enable, and delay counts from Obsidian launch.
- Settings panel and metadata tracking.
- Fetch log stored at `.obsidian/plugins/email2obsidian/fetch_log.json` keyed by `id` (not `emailId`); `fetch-new` appends to the log, `fetch-all` rewrites it to exactly the successfully fetched ids.
- Markdown creation, attachment download, and inline support.
- Safe filename generation and folder auto-creation.
  - Incremental fetch (log-aware dedupe) plus full fetch (log-ignoring, log-rewriting).
