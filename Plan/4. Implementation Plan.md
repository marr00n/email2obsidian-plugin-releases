Step-by-step refactor plan for Email2Obsidian

1) Prep and rebrand
- Install deps and confirm build works (`npm run build`/`dev`).
- Keep manifest id stable; update manifest/package names/descriptions/commands from HamsterBase to Email2Obsidian; remove unused HamsterBase code.
- Hard-code API base `https://email2obsidian.com/`.

2) Settings schema and persistence
- Define settings: `apiKey` (secret), `notesFolder` (required, default `E2Oinbox`), `attachmentFolder` (optional), `periodicSync` (toggle), `syncInterval` (1h/3h/6h/12h/daily), `runOnOpen` (toggle for one-time sync on app launch).
- Store via `loadData`/`saveData`; normalise folders; migrate any legacy keys if present.
- Track derived paths: fetch log `.obsidian/plugins/email2obsidian/fetch_log.json`; last run time (display only).

3) Settings UI
- Build settings tab fields for all settings above.
- Add helper text for API key expectations, folder creation behaviour, inline vs attachment handling, run-on-open/immediate-run behaviour.
- Add “Test connection” button calling `/api/emails` with `x-api-key`; treat HTTP 200 with valid shape as success; surface unauthorized/forbidden/rate-limit errors distinctly.

4) API client
- Create module wrapping `GET /api/emails`, `GET /api/emails/:id`, `GET /api/attachments/:id/download`; always send `x-api-key`.
- Support pagination via `cursor`/`nextCursor` + `hasMore`; parse `hashtags: string[]` and attachments `{ id, fileName, fileSize, mimeType, createdAt, contentDisposition }`.
- Bubble 401/403/429/5xx with friendly errors/backoff hints.

5) Fetch log
- Implement loader/writer for `.obsidian/plugins/email2obsidian/fetch_log.json` with shape `{ [id]: { fetchedAt, filename? } }` (no `emailId`, no attachments).
- Load at start of any sync; write atomically. `fetch-new` appends; `fetch-all` rewrites to successfully fetched ids.

6) Helpers: filenames and markdown
- `safeFilename(subject, createdAt)`: sanitise and, on collision, append incrementing numeric suffix (`-1`, `-2`, …) until unique per folder.
- `renderEmailMarkdown(email, attachments, paths)`: frontmatter (`title`, `created`, `tags` = hashtags + `email2obsidian`, `email2obsidianID`); body from `markdownBody`; replace guaranteed `![](data:...)` placeholders positionally with `![[<attachment path>/<inline fileName>]]`; list non-inline attachments under `## Attachments` using preserved `fileName`; references use attachment folder when set, otherwise note folder.

7) Attachment handling
- Ensure note + attachment folders exist; default attachments beside note if no attachment folder, otherwise always use attachment folder for inline and non-inline references.
- Download each attachment; preserve `fileName`, sanitise separators; on collision append incrementing numeric suffix until unique within the attachment folder (independent of note names).
- Return saved paths for inline replacement and attachment listing; log failures but continue per email.

8) Shared fetch-and-write pipeline
- Inputs: `apiKey`, destination/attachment folders, mode (`fetch-new` or `fetch-all`).
- Steps: validate credentials → load fetch log → list emails with pagination → select ids (fetch-new excludes logged ids keyed by `id`; fetch-all ignores log) → for each id fetch detail + attachments → write note/attachments with collision-safe filenames and inline replacement → update log (append for fetch-new, rewrite to successes for fetch-all) → emit notice summary (synced/skipped/errors) and console details.

9) Commands
- Add command palette entries: “Fetch New Email2Obsidian Notes” (mode fetch-new) and “Fetch All Email2Obsidian Notes” (mode fetch-all).

10) Scheduler
- Add periodic sync runner (fetch-new) at selected interval; guard overlapping runs with a mutex; clear timers on unload.
- Enabling periodic sync triggers an immediate run. Honor `runOnOpen` toggle for one-time sync on app launch; interval countdown starts on app open (no persisted timer state).

11) Error handling & safeguards
- Fail fast on missing/invalid API key; concise notices.
- Continue processing other emails if individual attachment downloads fail; log to console.
- Protect against partial writes (temp then rename where possible); ensure folder creation guarded.
- Surface rate-limit responses with backoff guidance; avoid log rewrites when a run aborts early.

12) Docs and verification
- Update README/manifest with setup steps, settings, commands, log path, collision behaviour.
- Manual test pass: missing creds, first sync, rerun zero rewrites, fetch-all reset, inline mapping, attachment listing, collision handling, periodic sync tick, run-on-open toggle, immediate run on enable, log persistence after restart (timer restarts), rate-limit notice.
- Add small unit tests for filename and markdown helpers if the harness allows; otherwise maintain the manual checklist.
