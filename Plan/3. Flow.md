# Flow — Email2Obsidian Obsidian Plugin

## 1. Initial Setup → Credentials + Folders Saved

User opens the plugin Settings tab.
- `API Endpoint` is hard coded as https://email2obsidian.com/
- Enters `API Key` (sent as `x-api-key`).
- Chooses `Destination Folder` (default `E2Oinbox`) (required)
- Chooses `Attachment Folder` (optional)
- Toggles `Periodic Sync` (off by default) and selects interval if enabled (1h, 3h, 6h, 12h, daily).
- Toggles `Run on open` to trigger an immediate sync when Obsidian launches; periodic delay starts fresh on each app open (no persisted countdown).

Plugin stores:
- Settings in Obsidian’s plugin data dir.
- Fetch log file `.obsidian/plugins/email2obsidian/fetch_log.json` keyed by `id` + `fetchedAt`.

Validations:
- Folder paths normalised; created on first sync if absent.

## 2. Shared Fetch-and-Write Pipeline (all commands)

Inputs:
- Endpoint (hard coded), `x-api-key`, destination folder, optional attachment folder.
- Selector mode: `fetch-new` (exclude logged ids) or `fetch-all` (include all ids).

Steps:
1) Validate credentials: if `x-api-key` missing/invalid, fail fast with a notice.
2) Load fetch log (`.obsidian/plugins/email2obsidian/fetch_log.json`) into memory; log is the dedupe source of truth.
3) List emails via `GET /api/emails` with pagination support (`cursor`, `sort`, `tag`, `search`), consuming `hasMore`/`nextCursor` from the response and expecting `hashtags` as `string[]`.
4) Select ids based on mode:
   - `fetch-new`: keep only ids not present in the log; logged-but-deleted locally remain skipped.
   - `fetch-all`: keep all ids; ignore the log for selection.
5) For each selected id:
   - `GET /api/emails/:id` to read `subject`, `markdownBody`, `hashtags`, `createdAt`, `attachments` (includes `id`, `fileName`, `fileSize`, `mimeType`, `contentDisposition`), and optional `emailId`/`expiresAt`.
   - For each attachment: `GET /api/attachments/:id/download` (uses provided `fileName`, `mimeType`).
6) Filename handling (shared): build safe filename from `subject`; on collision append an incrementing numeric suffix (`-1`, `-2`, …) until unique per folder for both notes and attachments.
7) Write note + attachments: ensure folders exist; compose Markdown (frontmatter: `title`, `created`, `tags` (hashtags + `email2obsidian`), `email2obsidianID`; body from `markdownBody`; before writing, replace each guaranteed `![](data:...)` placeholder in order with `![[<attachment path>/<inline fileName>]]` using the positional inline attachments (first placeholder → first inline attachment, second → second, etc.); inline vs attachment listing based on `contentDisposition`; if an attachment folder is set, all references use that folder).
8) Update log:
   - `fetch-new`: append newly fetched ids (only `id`, not `emailId`) with timestamps.
   - `fetch-all`: rewrite log to exactly the successfully fetched ids with timestamps/filenames.
9) Feedback: notice with synced count, skipped (for `fetch-new`), attachment download errors (also logged to console).

## 3. Command Triggers

### 3.1 Manual — “Fetch New Email2Obsidian Notes”
- Invoked from the command palette.
- Uses the shared pipeline with selector mode `fetch-new` (log-aware).
- Appends new ids to the log after successful writes; collision handling per shared rule.

### 3.2 Manual — “Fetch All Email2Obsidian Notes”
- Invoked from the command palette.
- Uses the shared pipeline with selector mode `fetch-all` (log-ignoring for selection).
- Applies the same collision-safe filename rule; rewrites the log to the fetched set on completion.
- Use-case: recovery after log issues, intentional re-import, vault restore.

### 3.3 Periodic Sync (Background)
- Scheduler invokes the shared pipeline with selector mode `fetch-new` at the chosen interval (1h, 3h, 6h, 12h, daily).
- Semantics identical to manual `fetch-new` (log-aware selection, collision-safe filenames, log append).
- Offers a `Run on open` toggle to optionally fire once when Obsidian launches; enabling periodic sync also triggers an immediate run.
- Interval countdown restarts on each Obsidian open (no persisted timer state).
- Errors surface via notices; detailed logs remain in console for debugging.

## 4. Attachment Handling Details

- Default: save next to note if no attachment folder set; otherwise use configured folder for both inline references and non-inline links.
- Preserve original `fileName`; sanitise path separators and collision-proof with incrementing numeric suffix per target folder (note folder and attachment folder independently).
- Use `contentDisposition` (always present) to embed inline attachments in-body and list non-inline attachments under `## Attachments`.
- Inline replacement: walk `markdownBody` and swap each guaranteed `![](data:...)` placeholder with the next inline attachment (positional mapping) using Obsidian embed syntax `![[<attachment path>/<fileName>]]`; leftover inline attachments (if any) still embed in-body, and non-inline attachments are listed separately.
- Large attachments: log failure but continue processing other emails.

## 5. Auth & State Expectations (Server-Side)

- All API calls authenticated via `x-api-key` header (same key for list, item, download).
- API is stateless; dedupe handled entirely by client `fetch_log.json`.
- Server supports pagination (`cursor` or `nextCursor`); client will request next page iteratively until no more pages are available.
- Attachment download endpoint must validate ownership via token; plugin does not expose token in saved files.
- Endpoints are rate limited; surface backoff hints in notices/console on 429-style responses.

## 6. Error Cases & Safeguards

- Missing/invalid credentials → fail fast with notice.
- Network/API errors → show summary; do not write partial frontmatter without body.
- Filename sanitisation prevents OS-incompatible chars; folder creation guarded.
- Fetch log write failures → warn; keep in-memory set for current run but mark UI that future runs may re-download.
